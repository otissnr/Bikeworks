📘 Cycling Spares App · Digital Bike Workshop
Concept document
This page captures the concept narrative for the Cycling Spares App / Digital Bike Workshop: a local-first, practical tool for managing bikes, spares, jobs and tools in a real workshop.

Vision

The Cycling Spares App (Digital Bike Workshop) is a concept for a local-first, practical tool that helps a rider or small workshop keep track of bikes, spares, tools and jobs in a way that matches how work actually happens on the bench.

Core ideas

  • Local-first: Data lives with the workshop first, with optional export or sync.
  • Bike-centric: Bikes and frames are the anchor objects; spares, tools and jobs orbit them.
  • Job-focused: Jobs link bikes, spares and tools, making it clear what is needed for each task.
  • Practical mapping: Spares are mapped to locations (bins, boxes, shelves) and to compatibility (which bikes they fit).

Entities

Bikes & frames

Bikes represent complete or in-progress builds. Framesets and test rigs are treated as first-class objects, allowing the workshop to track dedicated rigs for brake testing, drivetrain experiments and wheel work.

Spares & components

Spares include tyres, tubes, drivetrain parts, brakes, controls and small hardware. Each spare can be mapped to:

  • One or more bikes (compatibility)
  • One or more jobs (where it is used)
  • One or more locations (where it physically lives)

Tools & jigs

Tools cover core hand tools, torque tools, cable tools and chain tools. Jigs include 3D-printed fixtures, brake pad alignment tools, rotor spacers and wheel dish gauges. Tools and jigs are linked to jobs so each job has a clear tool list.

Jobs & tasks

Jobs are structured tasks such as brake service, drivetrain refresh or wheel work. Each job links:

  • One or more bikes
  • Required spares
  • Required tools and jigs
  • Optional notes and steps

Workshop flow

The app is designed to mirror how a real workshop operates:

  • Identify a job on a bike.
  • Check spares availability and compatibility.
  • Check tools and jigs required.
  • Execute the job and update state (wear, usage, notes).

Local-first data

The concept emphasises local-first data: the workshop owns its data, with optional export or sync. This keeps the tool lightweight, resilient and focused on practical use rather than cloud complexity.

Future directions

  • Shared build templates for gravel, commuter, touring and cargo bikes.
  • Shared job templates for common tasks.
  • Community-curated spares lists for specific bikes and use cases.

This Design Document page is intentionally concise. It can be expanded into a full specification, including data models, UI flows and integration points, but for now it serves as a readable, embedded concept inside the Digital Bike Workshop app.
